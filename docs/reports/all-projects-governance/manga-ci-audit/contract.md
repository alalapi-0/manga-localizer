## v2 comparison and access clarification

Effective candidate means base-to-working-tree net additions plus HEAD-to-index,
index-to-working-tree additions, and all untracked text. This prevents staged bad
content from hiding behind unstaged removal, while allowing current-tip forward
removal of paths introduced in intermediate commits. Clean CI equals base-to-head.

Inert committed Git objects, including repository paths mentioning Cursor, are
scanned for repository quality only. Their live filesystem counterparts are never
opened or resolved. A changed/untracked Cursor resource is rejected on status/path
metadata before any content read. Git-object and live-read coverage are separate.

Art lettering must reject an empty display-capability set with the established
409 response even when a generic fallback reports display role. No enqueue or
state advancement is allowed. Real image/font/data resources are not regression
fixtures. Ordinary routes and valid display-capability routes remain passing.

Governor v2 method clarification: the unchanged large-drift integration fixture
may reach either of the two demonstrated guards (global geometry bounds or
held-out geometry disagreement). Match only those complete known reasons; retain
a deterministic held-out case and direct matrix boundary cases. No v3 or budget
reset, no production geometry changes.

Governor v2 CI fixture clarification: the E2E spec may share a fixture-image
helper that uses the existing CI runtime only when both CI markers match. Every
other environment retains the guarded local wrapper. Four environment combinations
and the original two full E2E flows must pass; production storage guards are unchanged.
